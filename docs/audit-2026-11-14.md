# Project 180: audit, 14 November 2026

Scope: `main` at `d2d848c` (everything up to and including the food log, the program editor changes and the new exercise photos). The full audit of 13 November (`audit-2026-11-13.md`) still stands; this one checks what changed since and re-runs the checks that can run here.

## Short answer

- **No privacy or security problems found** in the new code. The food log, barcode lookup, photo estimates, site settings and nutrition targets all follow the rules: personal rows are always filtered by the signed-in person, staff reach a client only through `managedPerson`, the Claude key stays on the server, outside calls have timeouts, and the daily photo cap is enforced in one database write.
- **The database migrations are safe:** 0015 to 0017 only add tables and indexes. No table rebuilds, every foreign key is indexed, and "one per" rules are unique indexes.
- **Type check: clean.** TypeScript 5 over all packages and both apps, API tests included (about 1,400 files per app), no errors.
- **Shared unit tests: passing** (116 tests run with a stand-in for Vitest; the 3 weigh-in tests that use `expect.stringContaining` couldn't run in the stand-in and need the real run).
- **One inconsistency fixed** (below), plus a small cleanup gap.

## Fixed today

1. **Owners saw other coaches' clients in the lists.** The People page was changed to show only you and your own clients, but the Overview, the Messages inbox (and its unread badge), "Who's on what" and the Assign form's person picker still listed every client, including other coaches' (and Tilana's). ## Checked and fine

- Every API route file is behind `requireUser` (and `requireAdmin` for staff routes); the food routes inherit it from where they are mounted (`/me/food`, `/admin/users/:id/...`).
- Multi-row inserts all go through `insertMany`; no `.values(array)` that could pass D1's 100-value limit.
- Food inputs are capped (12 foods per add, a 92-day summary range, 2 MB photos, JPG/PNG/WebP only, 200-character hints, strict barcode format).
- The barcode reader (zxing WebAssembly) is bundled with the app; the Content-Security-Policy allows `wasm-unsafe-eval` and the camera for the app only.
- No hard-coded colours, no `window.confirm`, no bare `<select>` or date inputs outside the shared components, no `role === 'admin'` checks outside `isStaff`, and the phone app never mentions the admin.
- New screens start their grids with `grid-cols-1` and keep tap targets at 44px or more.
